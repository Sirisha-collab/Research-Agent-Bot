# React frontend setup

The Gradio UI is replaced by a React 19 + Vite 7 + TypeScript + Tailwind v4 app in `web/`.
The Python backend is unchanged except for two new report-download endpoints.

## Files in this update

| File | What it is |
| --- | --- |
| `backend/main.py` | replace — adds `/documents/{id}/report`, serves the built React app if present |
| `backend/core/report.py` | new — builds the Markdown report the UI downloads |
| `web/package.json` | new |
| `web/vite.config.ts` | new — dev proxy `/api` → `127.0.0.1:8000` |
| `web/tsconfig.json`, `web/tsconfig.app.json`, `web/tsconfig.node.json` | new |
| `web/index.html` | new |
| `web/.env.example` | new |

| `web/src/index.css` | new — Tailwind v4 theme tokens |
| `web/src/env.d.ts` | new |
| `web/src/types.ts` | new |
| `web/src/api.ts` | new — typed API client |
| `web/src/App.tsx` | new — layout and state |
| `web/src/components/*.tsx` | new — 9 components |

Unzip `research-assistant-web.zip` at the project root. It creates `web/` and overwrites
`backend/main.py`. `frontend/` (Gradio) and `run.py` can be deleted, or kept as a fallback.

## Prerequisites

- Everything from the original README (Python venv, `.env` with your Groq key)
- **Node.js 20.19+ or 22.12+** — Vite 7 requires it. Check with `node -v`, get it from
  https://nodejs.org (LTS)

## Development (two terminals)

**Terminal 1 — API**

```bash
cd research-assistant
.venv\Scripts\activate
uvicorn backend.main:app --reload --port 8000
```

**Terminal 2 — web**

```bash
cd research-assistant/web
npm install
npm run dev
```

Open http://localhost:5173. The dev server proxies `/api/*` to the backend, so there are no
CORS issues and no URL configuration.

## Production build

```bash
cd web
npm run build
```

This writes `web/dist/`. `backend/main.py` mounts that folder automatically when it exists,
so a single process now serves both:

```bash
uvicorn backend.main:app --port 8000
```

Open http://127.0.0.1:8000. The API docs stay at `/docs`.

For the built app, `VITE_API_URL` defaults to `/api`, which is wrong when the app is served
by FastAPI itself. Build with an empty base so calls go to the same origin:

```bash
# Windows PowerShell
$env:VITE_API_URL=""; npm run build
# macOS / Linux
VITE_API_URL= npm run build
```

Or create `web/.env.production` containing `VITE_API_URL=`.

## Pointing at a different backend

Create `web/.env.local`:

```
VITE_API_URL=http://192.168.1.50:8000
```

CORS is already open on the API side.

## What the UI does

- **Upload** — drag a PDF or click. The "explain and summarise" checkbox maps to
  `?understand=` on `/ingest`; uncheck it to index without spending LLM calls.
- **Summary** — always visible in the paper header card, not behind a tab.
- **Tabs** — Explanation, Findings (with a metrics table), Tables, Figures (click to zoom),
  Structure (section map with word-count bars), Ask.
- **Ask** — questions scope to whichever library papers are ticked; none ticked means search
  everything. Each answer collapses its sources with section, page and similarity score.
- **Downloads** — `report.md` and `document.json` are generated by the backend on demand,
  so nothing is written to disk until you click.

## Troubleshooting

| Symptom | Fix |
| --- | --- |
| `Backend unreachable at /api` | API isn't running, or it's on a port other than 8000 — update the proxy target in `vite.config.ts` |
| `npm install` fails on engine version | Node too old. Vite 7 needs 20.19+ or 22.12+ |
| Blank page after `npm run build` + FastAPI | Rebuild with `VITE_API_URL=` so requests go to the same origin |
| Figures show as broken images | The API must be running — images stream from `/documents/{id}/figures/{id}` |
| Tailwind classes have no effect | `@tailwindcss/vite` must be in `plugins` in `vite.config.ts`, and `index.css` must start with `@import "tailwindcss";` |
| Type errors on `import.meta.env` | `src/env.d.ts` is missing from the copy |
| Upload times out on a long paper | The client allows 20 minutes; a 60-page paper on a free-tier LLM can approach that. Uncheck "explain and summarise" to index first |

## Notes

- No state library, no router, no component library — one `App.tsx` holding state and nine
  presentational components. Adding TanStack Query or a router later is straightforward.
- The theme lives entirely in `@theme` at the top of `index.css`. Change `--color-accent`
  and the whole UI follows.
- Long ingests are a single blocking `fetch`. If you want a live progress bar, the natural
  next step is to have `/ingest` return a job id and poll a `/jobs/{id}` endpoint, since the
  pipeline already runs in discrete stages.
